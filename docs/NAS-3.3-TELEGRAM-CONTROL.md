# NAS 3.3: Telegram에서 수집 제어

기존 config/output 볼륨을 유지해 3.3.0으로 재빌드합니다. 이미 연결한 전용 봇과 개인 대화에서 아래 명령을 사용합니다. 관리 페이지를 열어둘 필요는 없습니다.

| 명령 | 동작 |
| --- | --- |
| `/collect` | NAS에 저장된 기본 단지 1개를 전체 수집 |
| `/collect 140634` | 등록된 해당 단지를 전체 수집 |
| `/status` | 현재 수집·GitHub 업로드 상태 |
| `/help` | 명령 안내 |

최대 3개 단지의 기존 순환 예약과 함께 사용합니다. `/collect`는 3개를 모두 실행하는 명령이 아닙니다. 단지 번호를 지정해 각각 요청할 수 있고, 현재 수집이나 업로드 중이면 추가 요청은 대기열에 쌓지 않고 상태를 알려줍니다. `/collect`는 성공 시 NAS 설정의 자동 업로드 여부를 따릅니다. 시작과 완료/실패 응답을 보내며, GitHub 업로드 완료를 공개 앱 배포 완료라고 표시하지 않습니다.

NAS의 Telegram 영역에 **명령 제어 켜기/끄기**가 있습니다. 기존 연결은 기본적으로 명령 제어가 켜집니다. 성공 자동 알림 설정은 명령 제어와 별개이며, 자동 알림을 꺼도 본인이 요청한 명령에는 응답합니다. 기존 토큰·수신 대화 정보는 다시 입력하지 않습니다.

메시지 수신은 약 3초 간격입니다. 연결한 본인의 개인 대화에서 본인이 보낸 명령만 처리합니다. 그룹, 다른 발신자, 봇 발신, 다른 단지 번호는 실행하지 않습니다. Telegram 최초 연결과 명령 수신이 같은 봇의 getUpdates를 동시에 호출하지 않도록 분리했습니다. 다른 프로그램과 봇을 공유하면 충돌할 수 있으므로 전용 봇을 사용합니다.

업데이트 ID는 실행 전에 `/config/telegram-control.json`에 저장합니다. 동일 업데이트를 재전달받거나 NAS가 재시작돼도 중복 실행하지 않습니다. 재시작 전·제어 재활성화 전의 오래된 명령은 실행하지 않습니다. 실행 직전 장애가 발생하면 해당 명령을 자동 재실행하지 않으므로 `/status` 확인 후 새 명령으로 요청합니다.

3.2.3의 매 실행 최초 새 문서 탐색 수정도 포함합니다. NAS를 업데이트하고 `/status` 응답을 먼저 확인한 다음 `/collect`를 보냅니다. Telegram 실계정/실수집 현장 확인은 사용자 NAS에서 필요합니다. 로컬 검사는 Telegram 응답과 수집 프로세스를 테스트 대역으로 사용해 인증·중복 방지·등록 단지·상태·완료 응답을 검증했습니다.
