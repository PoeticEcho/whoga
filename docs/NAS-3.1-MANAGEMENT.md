# 호가정리 3.1 관리 안내

## NAS에서 단지 추가와 실제 수집

1. 기존 config/output 볼륨을 유지하고 NAS 3.1 소스로 재빌드합니다.
2. NAS 관리화면의 **단지 추가 및 관리**에 네이버 단지 번호와 별칭을 입력합니다. 최대 3개입니다.
3. 주기와 자동 업로드 여부를 선택하고 **단지 설정 저장 · GitHub 반영**을 누릅니다. 기존 NAS GitHub 토큰으로 main의 수집 설정을 저장합니다.
4. 저장 후 단지별 **지금 전체 수집**을 누르면 그 단지를 표본 검사 → 전체 수집합니다. 자동 업로드가 켜져 있으면 성공 결과를 GitHub로 전송합니다.
5. **JSON 보기 / 저장**에서 단지별 최근 전체 수집 결과를 열어 확인합니다. 실패한 실행은 성공 JSON으로 표시하지 않습니다.
6. 공개 앱 탭은 설정의 단지 번호와 별칭을 따라 갱신됩니다. GitHub의 main 배포 주기(약 5분, 대기열에 따라 지연) 뒤 새로고침하세요. 아직 수집되지 않은 단지는 수집 대기로 표시합니다.

**제외**는 해당 입력칸을 비웁니다. 저장해야 수집 대상에서 빠집니다. 과거 수집 JSON은 삭제하지 않고 보관하며 공개 앱의 기존 자료는 보관 탭으로 남습니다. 단지마다 실제 네이버 카드 형식이 다를 수 있어 최초 실수집은 결과를 확인해야 합니다.

## Telegram

첨부 VideoBell의 getMe → webhook 확인 → 일회용 /start 연결 코드 → 개인 대화 확인 흐름을 참고해 독립 구현했습니다. 기존 앱 코드나 비밀 설정을 가져오지 않았습니다.

- BotFather에서 호가정리 전용 봇을 만들고 토큰 확인을 누릅니다.
- 봇 열기 링크에서 **시작**을 누른 뒤 NAS에서 **연결 확인**을 누릅니다. 코드 유효기간은 10분입니다.
- 테스트 발송으로 연결을 확인합니다. 자동 알림은 별도의 **업로드 성공 알림 켜기** 버튼으로 활성화합니다.
- 알림은 NAS → GitHub 전송 완료를 뜻합니다. 공개 앱 배포 완료로 표현하지 않습니다.
- VideoBell과 같은 봇을 공유하지 마세요. 기존 webhook을 자동으로 삭제하지 않습니다.
- 토큰은 NAS `/config/telegram.json`에 권한 0600으로 보관합니다. 공개 GitHub와 상태 API에는 노출하지 않습니다. Telegram 실제 연결/발송은 사용자가 토큰을 등록한 뒤 확인해야 합니다.

## 공개 앱

이름은 **호가정리**입니다. 이미지 생성으로 만든 건물·가격 막대 아이콘을 PNG로 압축했습니다. favicon 약 2KB, 앱 아이콘 약 3KB, OG 이미지 약 15KB입니다. SVG를 직접 그려 사용하지 않았습니다.

매물 목록의 **중개 개수 표시**를 끄면 텍스트·전체복사·TXT에서 해당 열을 제외합니다. 원본 JSON의 중개 개수는 유지합니다. 텍스트 맨 아래 **전체복사**는 현재 필터와 표시 옵션이 반영된 전체 텍스트를 복사합니다.

## 검증 범위

단지 선택 실행, JSON 경로 분리, Telegram 일회용 코드·개인 대화 확인·webhook 보존·토큰 마스킹, 텍스트 중개 열 옵션을 자동 테스트했습니다. 브라우저에서 NAS 관리 UI와 공개 앱 흐름을 확인했습니다. 실제 추가 단지 수집 및 실제 Telegram 발송은 클라우드에서 수행하지 않았습니다.
