# WhoGa 3.0: 최대 3개 단지 순환 수집

공개 앱의 **단지 관리**에서 네이버 단지 번호 1~3개와 주기를 저장합니다. GitHub `main/collection-plan.json`을 NAS가 읽고, 기존에 성공한 동일한 visible Chromium / Playwright CDP 환경으로 한 단지씩 수집합니다. NAS 재빌드 후에는 단지 변경을 위해 다시 빌드하지 않아도 됩니다.

## 주기의 의미

| 수집 간격 | 3개 등록 시 같은 단지 재방문 | 전체 수집 시도/24시간 |
| --- | --- | --- |
| 1시간 | 약 3시간 | 최대 24회 |
| 3시간 | 약 9시간 | 최대 8회 |
| 6시간 (기본) | 약 18시간 | 최대 4회 |

한 슬롯에 한 단지만 실행합니다. 첫 단지 → 두 번째 → 세 번째 → 첫 단지 순서입니다. 이는 18시간 동안만 운영한다는 뜻이 아니라 6시간 간격으로 계속 순환한다는 뜻입니다. 사이트 응답·수집 시간·NAS 재시작에 따라 실제 시각은 지연될 수 있습니다. 특정 주기가 사이트에서 항상 허용되거나 차단되지 않는다고 보장하지 않습니다.

## 설치·설정

1. 기존 프로젝트 폴더에 3.0 소스를 적용하고 Container Manager에서 재빌드·시작합니다. 기존 `/config`, `/output` 볼륨은 삭제하지 않습니다. 포트 8899, 메모리 3 GiB, `/dev/shm` 512 MiB, `/tmp` 512 MiB 설정을 유지합니다.
2. 공개 앱의 **단지 관리** 탭에서 단지 번호, 선택 사항인 별칭, 1·3·6시간 간격을 입력합니다.
3. `순환 수집 및 성공 후 자동 업로드 켜기`를 선택합니다. `PoeticEcho/whoga`의 Contents 읽기·쓰기 권한 토큰으로 저장합니다. 토큰은 이번 브라우저 요청에만 쓰며 localStorage에 보관하지 않습니다. NAS에 저장된 기존 업로드 토큰은 그대로 사용합니다.
4. NAS가 유휴 상태에서 최대 약 5분 간격으로 설정을 읽습니다. 적용 후 첫 단지를 바로 실행하고 다음 슬롯을 예약합니다. 실행/업로드 중이면 끝난 뒤 적용합니다.
5. 앱에서 **새로고침** 후 `NAS 3.0.0 적용 확인`과 적용 시각을 확인합니다. `GitHub 설정 저장됨`만 보이면 NAS 적용을 아직 확인하지 못한 상태입니다. 적용 기록은 `_state/nas-plan.json`에 남습니다.

원격 설정 파일을 처음 저장하기 전에는 기존 단일 단지 예약·토큰·자동 업로드 설정을 유지합니다. 기존 버전과 같이 새로운 코드 최초 시작 시 한 번 수집합니다. 이미 적용된 원격 설정이 꺼져 있으면 최초 시작 수집도 하지 않습니다. NAS 설정의 `공개 앱에서 저장한 단지·주기 설정 사용`을 끄면 원격 설정을 더 이상 읽지 않습니다.

## 데이터 흐름과 검증

- 설정: 공개 앱 → GitHub main `collection-plan.json` → NAS 유휴 시 적용 → GitHub 적용 확인 기록
- 관측: NAS full 수집 → `map-collector-v2/nas-imports/<단지번호>/<runId>.json` → 검증·변환 → GitHub Pages
- 140635의 기존 날짜별 자료는 `data/`를 유지합니다. 다른 단지는 `data/complexes/<번호>/`에 저장합니다. 한 단지의 실패가 다른 단지 자료로 표시되지 않습니다.
- 원문 단지번호, 카드 이름, 매매 유형, 카드 수, 묶음 참조, 매물번호 중복, 개별 호가를 검증합니다. 새 단지는 실제 카드의 동·면적 문자열을 사용하며 범어W의 78OB/84OA로 임의 변환하지 않습니다.
- 같은 날 더 최신 결과가 들어오면 이전 관측을 `_nas_<runId>.json`으로 보존하고 날짜 대표 자료를 갱신합니다. 제거한 단지의 기존 자료는 보관 탭으로 남깁니다.
- 단지는 최대 3개까지 활성화합니다. 아파트/오피스텔 매매의 현재 수집기 지원 카드 형식만 지원합니다. 혼합 유형, 0건, 이름·가격·필드 해석 불일치는 성공으로 처리하지 않습니다. 새 단지 실수집 성공은 실제 NAS 결과로 별도 확인해야 합니다.
- 순서는 실행 시작 전에 저장합니다. 실패·재시작 시 같은 슬롯을 즉시 반복하지 않고 다음 단지로 진행합니다. 네트워크 장애 시 마지막 정상 설정·관측은 보존합니다.

## 이번 검증과 남은 현장 확인

Python 테스트는 설정 제한, 순환·재시작, 실패 시 진행, 적용 확인 재시도, 3단지 경로 분리, 당일 이력 보존을 검증합니다. 브라우저 검사는 기존 자료, 단지 등록 폼, 토큰 비저장, 새 단지 동·면적 필터·브리핑, 수집 대기 화면을 확인합니다. 추가 단지 테스트는 합성 자료이며 실제 수집으로 기록하지 않습니다.

클라우드에서 NAS에 직접 접속하거나 재빌드하지 않았습니다. NAS에 3.0을 적용한 뒤 실제 추가 단지 JSON 도착과 앱 표시를 확인해야 합니다. 2026-10-26 수성범어W 122카드/581개별 매물의 이전 성공 기록을 새 단지 성공으로 재사용하지 않습니다.
