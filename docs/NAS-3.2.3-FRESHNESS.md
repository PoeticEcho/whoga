# NAS 3.2.3: 새 실행에서 이전 화면을 재수집하는 문제 수정

2026-11-02 사용자 PC 원문은 118건, NAS/공개 앱은 122건이라는 차이를 조사했습니다. GitHub 원본 기준 오늘 JSON은 08:04:03 KST, runId `973b070afe11406b99f6bf452d1bc797`, 122카드/590개별 매물입니다. 10월 27일 20:02 결과부터 11월 2일까지 카드·개별 매물 내용이 완전히 같고, 10월 28일 이후 로딩 관측은 매번 `[122]`였습니다.

기존 수집기는 동일 단지의 열린 문서를 유지했습니다. 이는 한 실행 안에서 표본 검사 후 전체 수집을 이어가는 데 필요했지만, 날짜가 바뀐 새 실행에도 적용되어 오래 열린 화면을 새 수집 시각으로 저장할 수 있었습니다. 카드 수 일치 검사는 이 경우도 통과합니다.

수정 후 NAS 실행의 최초 표본 단계에서는 같은 단지가 열려 있어도 원문 단지 주소로 새 문서를 엽니다. 그 실행의 표본→전체 단계에서는 새로 연 문서를 유지합니다. 브라우저·쿠키·보이는 데스크톱 환경은 유지하며, 매 카드마다 새로고침하지 않습니다. `target.documentNavigatedAt`과 `probe:document-opened` 로그에 문서 탐색 시각이 기록됩니다.

기존 config/output 볼륨을 유지해 3.2.3으로 재빌드한 다음 전체 수집을 실행합니다. 최신 원문의 실제 표시 수로 검증합니다. 118이나 122를 고정 기대값으로 사용하지 않습니다. 기존 10월 28일~11월 2일 기록은 수정하지 않았으며, 당시 원문을 새로 조회한 관측으로 보기 어렵습니다.

검증은 기존 122개 카드가 열린 브라우저에 다음 문서가 118개를 제공하도록 한 오프라인 회귀검사입니다. 두 번의 별도 실행에서 각각 새 문서를 열고 118개를 수집하며, 실행 내 표본/전체 사이에는 추가 탐색이 없음을 확인했습니다. 실제 NAS와 사용자 PC의 현재 원문을 같은 시각에 대조한 검사는 아닙니다. 업데이트 후 신규 JSON의 문서 탐색 시각·건수로 현장 확인해야 합니다.
